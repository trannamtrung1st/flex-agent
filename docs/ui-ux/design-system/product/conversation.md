# Conversation Surface

Flex Agent conversations are structured, auditable interactions with an onboard intelligence — not consumer chat.

The participant should feel they are **speaking with a present, responsive AI system inside the environment**, while the transcript remains readable and reviewable for long sessions.

## Default Composition

A live interaction surface typically contains:

1. compact session/agent telemetry
2. Agent Core within a bounded AI Observation Glass viewport or a compact
   Agent-presence anchor
3. conversation timeline
4. current input/voice control zone
5. optional contextual task/evidence panel

Use a conversation timeline rather than left/right speech bubbles.

The viewport establishes the feeling of addressing an onboard intelligence;
the transcript and composer remain on stable readable planes in front of or
adjacent to it. Do not place long conversation text beneath glass blur,
reflection, dither, or animated fields.

## Conversational Turn Anatomy

Each turn contains speaker identity, optional role, useful time/sequence metadata, content, attachments/structured content, optional references/evidence, and permitted turn actions.

## Agent Turn

- agent name/label plus compact identity mark linked visually to the Agent Core
- current/streaming turn may use a **thin blue signal rail** or localized blue edge
- reading typography: 15–18px; max width ~760px
- streaming marker only at the current generation boundary
- never put every agent response inside a bright blue bubble

## Participant Turn

- participant name or configured anonymized label
- same readable hierarchy as agent content
- neutral rail/marker rather than a competing brand color
- do not shrink participant answers into compact chat bubbles

## Separation

Use spacing, thin dividers, speaker markers, and rails. Special structured objects may use hull panels. Avoid giant rounded message containers.

## Input / Voice Zone

The active composer may feel more instrument-like than a messenger composer: dark inset surface, clear text/voice mode, microphone/live beacon state, scanner focus when active, and nearby connection/listening/processing state when useful.

Do not sacrifice familiar input affordances for theatrical styling.

## Actions

Copy, cite, inspect, retry, or review actions should be quiet and appear on hover/focus or in a small action row.

## Multi-Participant

Use consistent speaker labels, avatar/initial/identity marks, and role metadata. Color may help but cannot be the only speaker cue.
